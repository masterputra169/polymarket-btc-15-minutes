  C:\Users\Asus\.poly15\dashboard-password.txt

## 4. Live / dry-run switch

The topbar DRY RUN / LIVE badge is a button.

### Enable live money

1. Click the DRY RUN badge.
2. Read the warning.
3. Type LIVE exactly.
4. Click ENABLE LIVE.

The bot then:

1. checks no position is open;
2. preflights CLOB V2 init, readiness/allowance and non-zero pUSD;
3. writes DRY_RUN=false atomically to bot/.env;
4. exits cleanly; systemd restarts it in live mode (~10 seconds).

### Return to dry run

1. Click the LIVE badge.
2. Type DRY exactly.
3. Confirm. Open live positions must be settled first.

### Guardrails

- Wrong/lowercase confirmation rejected.
- Button disabled while paused or disconnected.
- Open positions block switching.
- If live startup fails (CLOB init/readiness/pUSD sync), the bot writes DRY_RUN=true, exits, and systemd restarts it in safe paper mode.
- Backend command is token-protected through the dashboard WebSocket.
- Live mode was not activated during this work.

### Separate accounting

| Data | DRY RUN | LIVE |
|---|---|---|
| State | state.json | state.live.json |
| Audit | state_audit.jsonl | state_audit.live.jsonl |
| Journal | trade_journal.jsonl | trade_journal.live.jsonl |
| Verified journal | verified_journal.jsonl | verified_journal.live.jsonl |
| Entry snapshot | entry_snapshot.json | entry_snapshot.live.json |

On live startup the bankroll is seeded from real pUSD. Live journal analytics and position values use live fills/state; paper history is not mixed in.

## 6. Recent fixes

### Bot restart loop

Watchdog read ptb_health.jsonl only after filter evaluation. A long signal-confirmation hold produced no heartbeat, so the watchdog restarted a healthy bot. Added recordPollHeartbeat() after every completed poll; liveness now advances during holds. Verified stable.

### Bankroll display

Startup log printed the configured default ($45.31) before state loaded. Now labeled Configured bankroll; actual state loads afterward. Dashboard shows PAPER CASH / PAPER EQUITY (or LIVE labels in live mode).

### Drift false positive

The alert compared live accuracy to offline test accuracy (76.84%) and used a file-mtime cutoff that saw only 31 trades. Fixed:

- filters journal trades by current model ID;
- uses a live same-model reference window (192–193 trades);
- requires a minimum live baseline;
- derives confidence baseline from live data;
- confidence is advisory, not a trigger.

Last check: 50-trade window 66%, live baseline 64.06%, CUSUM 0, driftDetected:false.

### Other delivery fixes

- CLOB V2 cold-import test timeout fixed for full-suite load.
- Cloudflare Insights CSP allowed; console error removed.
- Vite bundles split: app ~194 KB, react ~189 KB, motion ~139 KB, vendor ~4 KB.
